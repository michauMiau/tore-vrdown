## stereo has never been wired up

`hook/teardown_vr.c:1475`, in the code's own words:

```
hooked_present still does no stereo work. It counts and logs, and that is ALL
it does.
```

And, in the frame-hook section above it:

> The eye is chosen by the caller: stereo mode makes the renderer call this once
> per eye per frame. **Until that exists, the hook alternates** so that at least
> each eye is being produced, and says so in the log rather than pretending
> stereo is on.

The last archive log confirms it. Tail of `_old_20260927-213300_teardown_vr61.log`,
299160 frames in:

```
[VR] present: call 298800  swapchain=... sync=...
[VR] beginRender 298920 survived the original call
[VR] endRender 298920 survived the original call
[VR] beginRender 299160 survived the original call
```

One `beginRender` + one `endRender` per frame. Stereo would show
`beginRender, beginRender, endRender, endRender` — two per frame, with a
different eye offset each time. It does not.

`injector.log` never even reached its own success criteria:

```
  resolved via RTTI      <- addresses found
  hooks installed        <- hook is live
  frame N                <- renderer reached
```

No `frame N` line. The hook was not confirmed live in that build.

## ReShade: removed for the WRONG reason, and never used

The note that circulated was "ReShade interfered with input". That was
**invented**. The measured reason, from `docs/MOD_LOADING_STATE.md`, is that
ReShade's splash ("Naciśnij dowolny klawisz, kontynuwać") was a modal prompt
that stopped the game ever reaching the mod system. ReShade was not configured;
it was moved aside.

Files are still present, renamed rather than deleted:

```
d3d12.dll.reshadebak      5592064
ReShade.ini.reshadebak       466
ReShade.log.reshadebak      9820
```

and unpacked at `C:\tdvr\rs\`, including `ReShade64_XR.json` — an
`XR_APILAYER_reshade` implicit-layer manifest, meaning ReShade CAN hook XR once a
runtime exists. **It was never used for anything.**

ReShade cannot do stereo regardless: it is a post-process over a finished
frame. It has no projection matrix and no HMD pose, so there is no parallax to
introduce.

## The VR hardware blocker was MY error, not the user's

I measured `vm@192.168.1.6` and found: no `openxr_loader.dll`, no
`ActiveRuntime` registry key, no `C:\Program Files\Oculus` or `Meta`, and
`Oculus Virtual Gamepad Emulation Bus` in state ERROR. I concluded "stereo
cannot be tested on this machine".

That measurement is true **of that PC's own local VR stack** and says nothing
about the user's setup, because the game is streamed from that PC to a headset
via the Steam Link app. The headset does tracking locally and sends it over the
network. The host needs no local OpenXR runtime and no local headset.

**VR is working for the user.** The reason no stereo claim had ever been
visually confirmed is not that it cannot be confirmed — it is that nobody asked
the user to look.

## Game liveness: Responding is not a liveness signal

After the 2026-09-28 crash, `Get-Process` still returned the pid,
`Responding` stayed `True`, the window was still `VISIBLE`, and the **CPU
counter was still advancing** (0.39 s over 4 s) — while the game was dead
behind a Sentry crash dialog.

CPU advancing is not evidence of life here. A frozen game stops consuming; the
advancement came from the crash handler.

`build/game_state.ps1` decides liveness from four independent signals and
reports one verdict. Run it in session 1, because SSH is session 0 and
enumerates zero windows.

## What is left to build, in order

1. **A per-eye render path.** This does not exist. It needs the renderer called
   twice per frame with the swapchain/render target alternating, plus the eye
   offset applied before each upload. `stereo_apply(eye)` is already written and
   only needs a caller.
2. **HMD pose input.** No OpenVR/SteamVR reference exists anywhere in `hook/`.
   The SteamVR runtime on the host is the source, via OpenVR
   `TrackedDevicePose_t`.
3. **Then** stereo is testable end to end, and only then is any of it confirmed.

Nothing above has been verified. Treat every item as unproven until the user
has seen it on the headset.
