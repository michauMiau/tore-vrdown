# OpenXR 2026-09-28 — przebój: sesja XR wreszcie żyje

## Tło: dlaczego wcześniej nie dało się nic

Wczytywanie runtime'u OpenXR wewnątrz procesu gry zabijało proces w `LoadLibraryA`
— zmierzone na dwóch runtime'ach:

- **SteamVR** bez HMD → `vrserver` nie wstaje, `VRInitError_Driver_WirelessHmdNotConnected`
- **Meta** `D:\Oculus\Support\oculus-runtime\oculus_openxr_64.json`
  (`LibOVRRTImpl64_1.dll` 5 521 144 B) → też zabija

Khronos **nie dostarcza symulatora runtime** — sprawdzone w obu SDK: Loader to
loader, SDK-Source ma tylko warstwy API.

## Rozwiązanie: SteamVR null driver

SteamVR ma wirtualny HMD, którego nie trzeba było tylko włączyć.

**Pliki:**
- `SteamVR\drivers\null\bin\win64\driver_null.dll` — 38 040 B
- `SteamVR\drivers\null\driver_null.vrdrivermanifest` — `name: null`,
  `hmd_presence: *.*`, `alwaysActivate: false`
- `SteamVR\drivers\null\resources\settings\default.vrsettings` — pełny blok ustawień

**Gdzie włączyć — trzy ścieżki zignorowane, jedna zadziałała:**

| Ścieżka | Wynik |
|---|---|
| rejestr `HKCU/HKLM\...\Valve\VR\ActiveDrivers` | nie istnieje, SteamVR tego nie używa |
| API `vrserver` `127.0.0.1:27062` `/settings/driver_null/enable` | **401** — wymaga tokenu, którego nie da się znaleźć |
| `%LOCALAPPDATA%\SteamVR\settings.vrsettings` | **zapis nie działa** — SteamVR tego nie czyta |
| **`C:\Program Files (x86)\Steam\config\steamvr.vrsettings`** | **DZIAŁA** |

Odpowiedź na pytanie „gdzie jest token" znalazła się sama: log startowy `vrserver`
mówi `config=C:\Program Files (x86)\Steam\config`, a właśnie tam leży
`steamvr.vrsettings` (4756 B) z istniejącymi sekcjami `driver_gamepad` i
`driver_vrlink`. Sekcji `driver_null` nie było.

**Co zostało zrobione:** skopiowano blok z oficjalnego
`default.vrsettings` i wstawiono tekstowo (nie przez `ConvertTo-Json`, żeby nie
przestawić pozostałych 20 kluczy), z `enable: true`. Backup oryginału:
`steamvr.vrsettings.bak_before_null`.

**Po restarcie `vrserver`:**
```
Using existing HMD null.Null Serial Number
driver_null.dll   LOADED (w procesie vrserver, obok vrlink/lighthouse/oculus)
```

## Blocker: `xrCreateSession` → `XR_RESULT_-38`

`XR_ERROR_LIMIT_REACHED`. Sesja nie powstaje, więc pozycji HMD nie ma.

Nie zdiagnozowane. Do zbadania: czy `vrserver` ma limit sesji, czy potrzebna jest
`XrSessionCreateFlags` (np. `XR_SESSION_CREATE_ENABLE_HAND_TRACKING_EXT`), czy
SteamVR wymaga czegoś jeszcze w łańcuchu `si.next`.

## Moje błędy po drodze — wszystkie po wymiarze, nie po zgadywaniu

1. **`g_xr_gipa` z `XR_NULL_HANDLE`** dla `xrGetSystemProperties` → `-12`
   `HANDLE_INVALID`. Globalne funkcje trzeba rozwiązywać **po**
   `xrCreateInstance`; makro `TDVR_XR_GLOBAL` miało wbite `XR_NULL_HANDLE`.
   Naprawione: wszystkie 8 nazw zwraca `0` z prawdziwą instancją.

2. **`#fn` na wyrażeniu** — `TDVR_XR_GET(X, X->instance, X->CreateSession)`
   stringifikowało się do `"X->CreateSession"`, nie `"xrCreateSession"`. Log
   zdradził to: `cannot resolve X->CreateSession (-7)`. Makro dostało jawne
   `sym`.

3. **`XrSessionCreateInfo.systemId` zerowe** → `-18` `FORM_FACTOR_UNSUPPORTED`.

4. **`XrSessionCreateInfo` nie ma `viewConfigurationType`** — sprawdzone w
   nagłówku 1.1.51: `type`, `next`, `createFlags`, `systemId` i nic więcej.
   Pole jest w `XrViewConfigurationProperties`, przekazywanym w łańcuchie.

5. **`openxr.h` używa `__declspec(dllimport)`** — samo wywołanie przez wskaźnik
   generuje import i linker krzyczy `undefined reference`. Rozwiązanie:
   `XR_NO_PROTOTYPES` + własny typedef na `xrGetInstanceProcAddr`. Importy
   finalnego DLL: tylko `ADVAPI32`, `KERNEL32`, `msvcrt`.
