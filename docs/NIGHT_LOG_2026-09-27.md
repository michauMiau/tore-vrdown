## Three bugs in the test itself, worth remembering

The test failed at first for reasons that had nothing to do with the code it was
testing, which is the same class of mistake as the liveness checks earlier:

1. `sc_storage`, `g_vtable` and the code page were all carved out of one local
   array, so the stack layout overlapped them. Fixed by giving each its own
   aligned global.
2. `g_regions[4][2]` was sized for four regions but `region_add` was called
   five times. The fifth write overflowed into the adjacent `g_region_count`,
   which corrupted every later lookup. ASan caught it as a
   `global-buffer-overflow`; without ASan it just produced a segfault.
3. The fake `VirtualProtect` only accepted addresses inside the code page, but
   the write under test goes to the vtable. The install path failed for a reason
   unrelated to its logic.

Lesson: a test that fails for the wrong reason is worse than no test, because it
teaches you to distrust the thing that is actually correct.

## Rules that are now settled

- **Never steal bytes.** Use a vtable entry. `build_detour` works, but its
  failure mode is a delayed freeze with no fault address and no dump.
- **One change per build.** v52 vs v53 is the only comparison in this project
  that actually meant something, and it was only meaningful because exactly one
  thing differed.
- **Never conclude the game is alive from a process check.** `Get-Process` and
  `Responding` both report a frozen game as healthy. Use
  `build/monitor_run.ps1` in session 1.
- **Always press past the legal warning** before concluding anything.
